# Шаблон артефакта 7 — E2E-сценарии и баг-репорты

> **Практика**: 7 (содержательная, 6 баллов)
> **Проверка**: CI (`e2e-tests`) + LLM-рубрика + приём отчёта на занятии
> **Дедлайн**: 18.12.2026 (приёмка 04.12.2026)
> **Задание**: [`materials/module-07-e2e/practice/practice-07.md`](../module-07-e2e/practice/practice-07.md)

## Что сдаёте

E2E-тесты в модуле `e2e-tests` + джоб `e2e-tests` в GitHub Actions + отчёт (`docs/practice-7/e2e-report.md`), включающий результаты прогона против сборки с внесёнными дефектами и баг-репорты по найденным дефектам.

## Состав отчёта (`docs/practice-7/e2e-report.md`)

```markdown
# E2E-отчёт: <объект тестирования>

## 1. Summary
| Всего сценариев | Пройдено (обычная сборка) | Упало (сборка с дефектами) | Оформлено баг-репортов |

## 2. Сценарии
### SC-001: <название>
- Шаги, результат PASS/FAIL, трёхзвенная проверка (ответ, БД, асинхронный след)

## 3. Прогон против сборки с дефектами
| Проверка | Сценарий | Звено | Ожидали | Получили |

## 4. Баг-репорты
### BR-001: <заголовок>
- Шаги воспроизведения (STR)
- Ожидаемый результат
- Фактический результат
- Доказательства: ответ, состояние БД, асинхронный след
- Severity / Priority
- Связанный сценарий (SC-NNN)
```

## Требования

- Не менее 5 сценариев: покупка, возврат, declined-кейсы; минимум один технический сценарий (отказ брокера, DLQ, недоступность зависимости).
- Каждый сценарий проверяет полную цепочку сервисов и **три звена**: ответ Gateway, состояние БД, асинхронный след.
- Данные создаются внутри сценария; ожидания — через Awaitility, без `Thread.sleep`.
- Джоб `e2e-tests` в GitHub Actions поднимает стек и прогоняет набор; прогон на обычной сборке зелёный и демонстрируется на приёмке.
- Прогон набора против сборки `practice-7-bugs` выполнен; падения разобраны по звеньям.
- **Баг-репорты: не менее 3.** Каждый по единому шаблону курса (модуль 2, лекция 4, слайд 42): заголовок, STR, ожидаемый и фактический результат, severity, priority, связанное требование.
- Каждый баг-репорт воспроизводится на сборке `practice-7-bugs`, соответствует реально внесённому дефекту и связан со сценарием `SC-NNN`.
- Отчёт: что проверяли, какие данные, результаты, найденные проблемы, что осталось непроверенным.

## Как сдавать

Ветка + Issue с label `practice-7` и ссылками на репозиторий, ветку и Actions run. CI прогоняет E2E-набор; LLM находит отчёт в ветке по каноническому пути и проверяет по рубрике; отчёт защищается на проходной практике.
