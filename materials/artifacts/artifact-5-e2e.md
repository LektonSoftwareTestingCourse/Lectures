# Шаблон артефакта 5 — E2E бизнес-сценарии и баг-репорты

> **Практика**: 5 (содержательная, 6 баллов)
> **Проверка**: CI (`e2e-tests`) + LLM (`skill-2`)
> **Дедлайн**: конец недели 11

## Что сдаёте

E2E-тесты + отчёт (`docs/practice-5/e2e-report.md`), включающий баг-репорты по найденным при прогоне дефектам.

## Состав отчёта (`docs/practice-5/e2e-report.md`)

```markdown
# E2E-отчёт: <объект тестирования>

## 1. Summary
| Всего сценариев | Пройдено | Упало |

## 2. Сценарии
### SC-001: <название>
- Шаги, результат PASS/FAIL, трёхзвенная верификация

## 3. Баг-репорты
### BR-001: <заголовок>
- Шаги воспроизведения (STR)
- Ожидаемый результат
- Фактический результат
- Severity / Priority
- Связанный сценарий (SC-XXX)
```

## Требования

- Не менее 5 сценариев: покупка, возврат, declined-кейсы.
- Каждый сценарий проверяет полную цепочку сервисов.
- Отчёт: что проверяли, какие данные, результаты, найденные проблемы.
- **Баг-репорты: не менее 3.** Каждый содержит заголовок, шаги воспроизведения, ожидаемый результат, фактический результат, severity и priority.
- Баг-репорты оформляются **по итогам реального выполнения E2E-сценариев** — каждый связан со сценарием, на котором воспроизведён дефект.
- Теория баг-репортов дана в модуле 2 (лекция 4); здесь она применяется на практике.

## Как сдавать

Ветка + Issue с label `practice-5`. CI прогоняет E2E-набор; LLM проверяет отчёт по рубрике `skill-2`.
