## Цель практики

Расширить покрытие unit-тестами для сервисов Switch и Card-Management. Научиться использовать параметризованные тесты для проверки множества сценариев (классы эквивалентности, границы) одним методом. Настроить плагин JaCoCo для измерения покрытия кода в CI.

**Образовательная задача**: студент осваивает параметризованные тесты JUnit 5, учится писать читаемые названия тестов (should...When...) и обеспечивать Branch Coverage ≥ 70%.

## Часть 1. Демонстрация (0:00–0:15)

Преподаватель на экране:
1. Открывает сервис `card-management`.
2. Создает тест для `CardManagementService.checkLimits()`.
3. Демонстрирует `@ParameterizedTest` с `@CsvSource`:
   - Тестирует суммы: меньше лимита, равно лимиту, больше лимита.
4. Показывает, как JaCoCo плагин генерирует отчёт.
5. Показывает, как в CI проверяется Branch Coverage.

**Скрипт для преподавателя:**

> Смотрите. У нас в Card Management есть логика проверки дневного лимита. Вместо того чтобы писать 10 одинаковых методов, мы пишем один `@ParameterizedTest`. В `@CsvSource` передаём строки: сумма, ожидаемый результат. JUnit сам прогонит метод для каждой строки. И заметьте: мы покрываем и ветку `true`, и ветку `false` в условии `if (amount > limit)`. Это и есть Branch Coverage. Добавим JaCoCo в pom.xml — он создаст XML-отчёт, и наш CI-пайплайн будет падать, если покрытие < 70%.

> Критерии сдачи. Вы должны покрыть бизнес-логику Switch и Card Management параметризованными тестами. Названия тестов должны быть читаемыми: `shouldDeclineWhenCardIsBlocked`.

## Часть 3. Самостоятельная работа (0:20–0:80)

### Шаг 1. Parameterized tests для Switch

1. Создайте `SwitchServiceTest`.
2. Напишите параметризованный тест для маршрутизации транзакций:
   - `@CsvSource({"400000, ISSUER_A", "400001, ISSUER_B"})`
3. Проверьте, что Switch корректно извлекает BIN и направляет нужному эмитенту.

### Шаг 2. Негативные сценарии для Card Management

1. Напишите тесты для статусов карт: `ACTIVE`, `BLOCKED`, `EXPIRED`.
2. Используйте `@EnumSource(CardStatus.class)` для перебора всех статусов.
3. Проверьте отказы для `BLOCKED` и `EXPIRED`.

### Шаг 3. Настройка JaCoCo

В `pom.xml` добавьте:
```xml
<plugin>
    <groupId>org.jacoco</groupId>
    <artifactId>jacoco-maven-plugin</artifactId>
    <version>0.8.11</version>
    <executions>
        <execution>
            <goals><goal>prepare-agent</goal></goals>
        </execution>
        <execution>
            <id>report</id>
            <phase>test</phase>
            <goals><goal>report</goal></goals>
        </execution>
    </executions>
</plugin>
```

Запустите `mvn test` и проверьте отчёт в `target/site/jacoco/index.html`.

## Часть 4. Разбор типовых проблем (0:80–0:90)

| Проблема | Решение |
|----------|---------|
| Coverage < 70% | Проверьте Branch Coverage. Возможно, не покрыты ветки `else` в условиях. |
| `ParameterResolutionException` | Параметры в `@ParameterizedTest` не совпадают с аргументами метода. |
| Тесты падают в CI, но работают локально | Проверьте, что данные не зависят от времени или состояния. |
| JaCoCo отчёт пустой | Убедитесь, что `prepare-agent` выполняется до `test` фазы. |
