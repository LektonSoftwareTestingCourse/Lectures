# Тестирование ПО: от модуля до стратегии

> **Курс для 4 курса ИТМО** • 16 лекций + 16 практик • 1 семестр • Дистанционно
>
> Курс читают **действующие инженеры Lekton** — компании-разработчика ПО для
> процессинговых центров.

---

## О курсе

Курс предполагает 32 занятия (16 лекций + 16 практик), полную совместимость с личным ноутбуком студента и
простую логику — постепенное движение от запуска тестовой среды к тест-дизайну,
unit-тестам, API и интеграционному тестированию, E2E-сценариям и финальной
тестовой стратегии. Курс не покрывает технические аспекты UI тестирования.

**Оптимальный стек:** Java 21, Spring Boot 3, JUnit 5, REST-assured,
Docker Compose, PostgreSQL, RabbitMQ, GitHub Actions, Allure Reports.

Студенты получают проект **СМП** (симулятор процессингового центра) без тестов и
пишут тесты заново от модуля к модулю, формируя портфолио к концу семестра.

---

## Программа курса

### Модуль 1. Введение в тестирование и enterprise-системы
*2 лекции + 2 практики*

Зачем тестировать, жизненный цикл ПО, verification vs validation. Процессинговый
центр как предметная область: путь банковской транзакции, микросервисная
архитектура СМП. На практике 1 — запуск СМП через Docker Compose,
health-check'и, Git-воркфлоу. Практика 2 — проходная: приём артефакта 1,
разбор архитектуры СМП и построение карты требований.

### Модуль 2. Тест-дизайн и техники тестирования
*2 лекции + 2 практики*

Классы эквивалентности, граничные значения, таблицы решений, state-transition
диаграммы, исследовательское тестирование. На практике — проектирование
тест-кейсов по требованиям СМП, оформление баг-репортов, peer review.

### Модуль 3. Пирамида тестирования и основы CI/CD
*2 лекции + 2 практики*

**Test Pyramid** vs Testing Trophy, антипаттерны, quality gates. **GitHub Actions:**
workflows, триггеры, матричные сборки. На практике — обзор инструментов
(JUnit 5, REST-assured, Mockito) и настройка CI-пайплайна для СМП.

### Модуль 4. Unit-тестирование на Java / JUnit 5
*2 лекции + 2 практики*

Принципы **FIRST**, паттерн **AAA**, test doubles (**Mockito**). Code coverage
(**JaCoCo**), анализ покрытия и качества тестов. На практике — написание
unit-тестов для бизнес-логики Gateway, Switch и Authorization, достижение
branch coverage ≥ 80%.

### Модуль 5. API-тестирование REST-сервисов
*2 лекции + 2 практики*

REST, статус-коды, контракты (**OpenAPI**). **REST-assured**, JSON Schema
validation. Позитивные и негативные сценарии, идемпотентность. На практике —
тестирование Gateway и Switch, сквозной проход транзакции с проверкой
decline-кодов.

### Модуль 6. Интеграционное тестирование с БД
*2 лекции + 2 практики*

Интеграционное тестирование с БД в контейнерах: PostgreSQL, RabbitMQ.
Особенности тестирования persistence-слоя: миграции, тестовые данные,
изоляция тестов. На практике — интеграционные тесты для Card Management,
Transaction Logger и Authorization с поднятием реальной БД в контейнере.

### Модуль 7. E2E и тестирование бизнес-сценариев
*2 лекции + 2 практики*

Бизнес-сценарии vs технические, проверка полного пути транзакции через все
сервисы. Тестовые данные, flaky-тесты. На практике — E2E-сценарии: покупка,
возврат, declined-кейсы с полной верификацией цепочки.

### Модуль 8. CI/CD, отчётность и тест-менеджмент
*2 лекции + 2 практики*

Продвинутый CI/CD: параллельный запуск, кэширование, нагрузочный smoke.
**Allure Reports**, coverage trends. Риск-ориентированное тестирование, тестовая
стратегия. На практике — доработка пайплайна, нагрузочный прогон 500+
транзакций, составление и защита финальной тестовой стратегии.

## Практические работы

Каждая практическая работа — самостоятельный артефакт, который студент сдаёт
через Git (ветка + Pull Request). Проверка комбинированная: CI-автопроверка
для кодовых работ, LLM-проверка для текстовых артефактов.

| № | Практика | Ключевые требования |
|:---:|---|------|
| 1 | **Запуск СМП + smoke-тесты** | Все сервисы в UP, Git-воркфлоу, smoke-отчёт |
| 2 | **Тест-дизайн и баг-репорты** | ≥ 15 тест-кейсов, ≥ 3 техники, ≥ 5 баг-репортов |
| 3 | **Unit-тесты на JUnit 5** | Branch coverage ≥ 80%, ≥ 20 методов, Mockito |
| 4 | **API и интеграционные тесты** | Все endpoint'ы, все decline-коды, БД в контейнере |
| 5 | **E2E бизнес-сценарии** | ≥ 5 сценариев, полная проверка цепочки сервисов |
| 6 | **CI/CD и нагрузочный smoke** | Pipeline green, coverage ≥ 80%, p95 < 2 сек |
| 7 | **Отчётность и метрики** | Allure с историей, coverage trends, выводы |
| 8 | **Финальная тестовая стратегия** | Coverage map, ≥ 5 рисков, индивидуальная защита |
